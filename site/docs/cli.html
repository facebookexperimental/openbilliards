Reference — native harness

CLI reference

pool-cli is the native measurement harness: it runs the same kernel source as the shipped wasm and CI byte-compares their records on every platform. One scenario JSON in, one shot record out, plus deterministic batches, parameter sweeps, oracle diffs and trajectory CSVs docs/sdk/README.md.

01 — Build & invoke

Build & invoke

Shell — verified cargo 1.98

cargo build -p pool-cli --release   # --release: 200 breaks take ~0.3 s
target/release/pool-cli version

Output

pool-cli 0.1.0
kernel_version: 0.1.0+snapshot
shot_record format_version: 1
scenario schema: {system, shot, options?} (see pool-cli run --help)
oracle fixture format: openbilliards.oracle.v1

The hash suffix identifies the exact build: records refuse to replay across builds. Every subcommand documents itself with --help. Exit codes: 0 pass, 1 comparison failed (compare only), 2 error.

02 — run

run — one scenario, one record

FlagDoes
--scenario <in.json>The scenario document (required).
--out <record.json>Write the ShotRecord.
--options-presetdefault | realistic | mathavan-fitted | grip-fitted. REPLACES the scenario's options; the fitted presets also patch table.cushion_response (they are joint fits).
--equipment axis=id,…Compose from catalog ids (axes table|cloth|ballset|cue|cushion_model). Rack scenarios re-rack on the resolved composition; explicit placements keep geometry. Mutually exclusive with --options-preset.
--seed <u64>Re-rack seeded rack scenarios on a new seed.
--eventsPrint the event stream.

simulate is a deprecated alias of run.

Shell — verified, seeded break with event stream

pool-cli run --scenario docs/sdk/scenarios/break.json --seed 7 \
             --out break_7.json --events

#1    t=0.099330     BallBall[0, 1]

#3    t=0.099398     BallBall[3, 5]
…
wrote break_7.json: 97 events, duration 7.625556 s

03 — batch & sweep

batch & sweep — studies

batch runs a seed range (--seeds A..B or A..=B) and/or a shot-parameter sweep (--sweep spec.json) in parallel; output is identical for every --threads value. Rows land in --out results.jsonl as {i, seed, <overrides>, events, duration, pocketed}; a summary always prints.

Shell — verified, 100-seed break study

pool-cli batch --scenario docs/sdk/scenarios/break.json --seeds 0..100 \
               --options-preset realistic --out results.jsonl

Output

batch: 100 shots, 0 errors
pocketed: total 113, per-shot min 0 / mean 1.13 / max 3
pocketed by ball: 0:2 1:1 3:3 4:6 5:54 6:22 7:2 8:5 9:18
events: min 71 / mean 92.5 / max 121
duration [s]: p10 6.814 / p50 8.055 / p90 9.282 / max 11.861

(0:2 reads: two scratches.) A sweep spec is {"param": "phi"|"v0"|"theta"|"a"|"b", "from", "to", "steps"}; an array of specs makes a cartesian grid, last axis fastest. sweep takes exactly two specs and emits CSV columns <p1>,<p2>,events,duration,n_pocketed,pocketed,error.

Shell — verified, aim grid filtered to potting rows

cat > aim.json <<'SPEC'
[{"param": "phi", "from": 1.45, "to": 1.75, "steps": 13},
 {"param": "v0", "from": 1.5, "to": 3.0, "steps": 2}]
SPEC
pool-cli sweep --scenario docs/sdk/scenarios/cut_side.json --sweep aim.json \
    | awk -F, 'NR==1 || $5 > 0'

Output — head

phi,v0,events,duration,n_pocketed,pocketed,error
1.45,1.5,11,7.545786386594051,1,0,
1.45,3,11,4.61883795857515,1,1,
1.525,1.5,12,4.762844087531531,1,1,
…
1.6,1.5,14,7.466583098505995,1,1,

Read pocketed ids directly: ball 0 means a scratch: here φ = 1.45 needs 3 m/s (soft speed scratches), φ = 1.525 pots at soft speed.

04 — sample

sample — trajectories from records

FlagDoes
--record <record.json>A record from the SAME kernel build (strict replay).
--t <seconds> XOR --fps <hz>One instant, or a uniform grid; the final time is always included.
--format csv|jsonCSV columns t,ball,x,y,z,qw,qx,qy,qz,motion; JSON emits frames of ball samples.
--out <file>Write instead of stdout.

Shell — verified, 60 fps CSV for plotting

pool-cli sample --record break_7.json --fps 60 --format csv --out frames.csv
head -3 frames.csv

Output

t,ball,x,y,z,qw,qx,qy,qz,motion
0,0,0,-0.635,0.028575,1,0,0,0,Sliding
0,1,0,0.635,0.028575,1,0,0,0,Stationary

Records store only events; the kernel sampler reconstructs the exact analytic state at every query time: 4,590 rows here (10 balls × 459 frames), never resampled physics concepts · records.

05 — compare

compare — oracle diffs

Diff a record against an oracle fixture (openbilliards.oracle.v1): gates the event-type sequence, per-event |dt| (--tol-time, default 1e-6 s), and final positions (--tol-pos, default 1e-4 m). Exit code 1 on a failed comparison.

Shell — verified, two-cushion bank vs committed oracle

pool-cli run --scenario docs/sdk/scenarios/bank.json --out bank.rec.json
pool-cli compare --ours bank.rec.json \
    --oracle crates/pool-core/tests/fixtures/oracle/bank_two_cushion.json

Output

comparing 12 events (ours, Rest excluded) vs 12 (oracle); tol-time 1.0e-6 s, tol-pos 1.0e-4 m
#0   ok   Strike[0]  dt=0.000e0  b0: dpos=0.000e0 dvel=4.441e-16
#1   ok   BallLinearCushion[0][11]  dt=0.000e0  b0: dpos=1.743e-6 dvel=0.000e0
…
final b0 ok    dpos=1.340e-6 dvel=0.000e0
result: PASS

Note: some fixtures carry documented model-difference waivers with looser per-event |dt| bounds (e.g. straight_pot needs --tol-time 2e-4); see crates/pool-core/tests/fixtures/oracle/waivers.json.

07 — Scenario files

Scenario-file conveniences

pool-cli’s loader, and ONLY its loader, expands two conveniences in committed scenario files: "system": {"rack": "nine" | "fifteen"} (a seeded WPA rack built from shot.seed, so seed sweeps re-rack per shot) and "system"."table": "wpa_9ft" (the trunk table preset). Unknown top-level keys are ignored, so scenarios can carry description and provenance fields.

Note: the wasm simulate_json and both SDKs reject these shorthand forms. Expand racks there via Engine.nineBallRack() / SystemState.nine_ball_rack() instead docs/sdk/README.md.

Eight golden scenarios ship in docs/sdk/scenarios/: break, cut_side, bank, draw, kick, lag, jump, masse, each self-describing and simulated end-to-end in the CLI's test suite.
