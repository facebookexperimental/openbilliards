Reference — CPython ≥ 3.9

Python SDK

pool_py binds the same kernel crate that powers the wasm build: zero physics reimplementation. Simulation releases the GIL, batches parallelize deterministically, and sampling returns numpy arrays: an analysis and reinforcement-learning surface, not a port crates/pool-py/README.md.

01 — Install

Install

Shell

# development install into the active venv (needs Rust + maturin)
cd crates/pool-py
maturin develop --release        # add --uv inside a uv-managed venv

# or build the abi3 wheel: one per platform covers CPython ≥ 3.9
maturin build --release          # target/wheels/pool_py-*.whl
pip install target/wheels/pool_py-*.whl

Verify the build by asking the kernel who it is: python -c "import pool_py; print(pool_py.kernel_version())". The version hash is stamped into every record this module produces.

03 — Batch analysis

A hundred breaks, one call

Each seed re-racks the nine balls with seeded micro-gaps, so a seed range measures the break-outcome distribution. Results come back in order regardless of thread count.

Python — verified CPython 3.12, pool_py 0.1.0

import math
import numpy as np
import pool_py as pp

scenarios = [
    (pp.SystemState.nine_ball_rack(seed), pp.Shot(v0=9.0, phi=math.pi / 2, seed=seed))
    for seed in range(100)
]
records = pp.batch_simulate(scenarios, options=pp.SimOptions.realistic())

pocketed = [sum(e["kind"] == "ball_pocket" for e in rec.events()) for rec in records]
print("mean balls pocketed on the break:", sum(pocketed) / len(pocketed))

ts = np.linspace(0.0, records[0].duration, 500)
frames = records[0].sample_batch(ts)   # (T, N, 8): x y z qw qx qy qz code
np.savetxt("cue_path.csv", np.c_[ts, frames[:, 0, :3]], header="t,x,y,z")

Output

mean balls pocketed on the break: 1.15
# frames.shape == (500, 10, 8); cue_path.csv written

Rows of sample(t) / sample_batch(ts) follow ball_ids() order. The trajectory is reconstructed exactly from the analytic motion; records store events, never frames concepts · records.

04 — The RL loop

Deterministic, headless, fast

The kernel is an event solver, not a frame stepper: a full break resolves in milliseconds with no renderer attached, and the same seed and parameters produce byte-identical records on any machine. That is the whole contract a training environment needs: a state in, a shot in, an exact table state out.

Python — verified CPython 3.12, pool_py 0.1.0

import math, time
import pool_py as pp

state = pp.SystemState.nine_ball_rack(7)
t0 = time.perf_counter()
for episode in range(20):
    # a crude policy: sweep the break angle a little each episode
    shot = pp.Shot(v0=8.0, phi=math.pi / 2 + 0.002 * episode, seed=episode)
    rec = pp.simulate(state, shot)          # releases the GIL
    final = rec.sample(rec.duration)        # numpy (N, 8) table state
    on_table = (final[:, 7] != 4).sum()     # motion code 4 = Pocketed
dt = time.perf_counter() - t0
print(f"20 full breaks in {dt:.2f}s, last on_table={on_table}")

Output — one laptop core, no rendering

20 full breaks in 0.05s, last on_table=9

Scale up with batch_simulate (thread-parallel over a scenario list) or sweep (one state, many candidate shots); both are deterministic and order-stable for any threads value, so an experiment is reproducible from its seed list alone feature 005 (internal spec).

05 — Errors & determinism

Errors & determinism

Kernel input rejections and malformed JSON surface as ValueError carrying the kernel's own message (batch errors are prefixed scenario {i}:); budget exhaustion and internal invariants are RuntimeError. No panic ever crosses the FFI boundary crates/pool-py/README.md.

Python — verified error and determinism checks

>>> pp.SystemState.nine_ball_rack(1, cloth="velvet")
ValueError: invalid input: unknown equipment cloth id "velvet"

>>> a = pp.simulate(state, pp.Shot(v0=8.0, phi=math.pi / 2, seed=3)).to_json()
>>> b = pp.simulate(state, pp.Shot(v0=8.0, phi=math.pi / 2, seed=3)).to_json()
>>> a == b
True

ShotRecord.from_json is strict: the record's format version and kernel version must match this build, because cross-build replay is not bit-reproducible concepts · determinism. to_json() round-trips floats losslessly.
