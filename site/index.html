The record

Anatomy
of a break.

One recorded break, event by event. The kernel solved it once, in closed form; what moves here is the record itself, an event list that re-simulates byte-identical on any machine Constitution. Every tick on the rail is read off the record, not an animation keyframe.

Performance

The break,
in 4 milliseconds.

Between events the kernel evolves ball motion in closed form; collision times are the real roots of degree-≤4 polynomials, found with the kernel’s quartic root solver. No timesteps, no accumulated error. A time-stepping engine would need roughly 30,000 steps to hold the same tolerance over one shot physics-engines.md · §4.

That makes it an order of magnitude faster than the leading open-source research simulator, measured on a harder workload: its 9-ball break averages 35.9 ms per shot the simulator performance study (internal); our 15-ball break settles in 3.76 ms native with compliant multibody cluster resolution the internal verification archive.

Determinism

Same shot, same bytes,
any machine.

The kernel is a pure function: initial state, shot parameters, and a seed go in; an event list comes out. No ambient randomness, no wall-clock reads, no NaN. The canonical build is a single .wasm binary, bit-exact across platforms by the WebAssembly spec, so determinism is a build property, not a discipline problem Constitution.

A replay is just shot parameters plus a seed. It re-simulates bit-exactly anywhere, forever verifiable. Every record embeds the kernel version hash, so cross-version replay is rejected by design.

Cross-OS gate, every merge X86_64 ≡ ARM64 CI byte-compares record JSON between ubuntu-latest and macos-latest; any difference fails the build. ci.yml · determinism

Open source + SDK

Script it. Study it.
Train on it.

Three control surfaces over one kernel: a CLI with run, batch, sweep, compare, and sample subcommands; a plain-ESM TypeScript SDK for node and browser; and a PyO3 Python module whose batch simulation releases the GIL and returns numpy (N, 8) arrays. All three consume the same JSON scenario schema.

Deterministic, headless, seeded, and fast enough for roughly 10,000 physics-true shots per second per core the internal verification archive: a research and AI-training substrate in everything but the gym wrapper, which does not ship yet. Rollouts reproduce exactly: same state, same parameters, same seed, same bytes Constitution.

# 100 seeded breaks, in parallel, deterministically
import math
import numpy as np
import pool_py as pp

scenarios = [
    (pp.SystemState.nine_ball_rack(seed),
     pp.Shot(v0=9.0, phi=math.pi / 2, seed=seed))
    for seed in range(100)
]
records = pp.batch_simulate(scenarios,
    options=pp.SimOptions.realistic())  # GIL released

ts = np.linspace(0.0, records[0].duration, 500)
frames = records[0].sample_batch(ts)  # (T, N, 8) float64

The field

The field,
read honestly.

The seat for simulation-grade physics with modern delivery on an open platform is currently empty: the old physics benchmark is essentially untouched since 2015, and the realism leader never shipped on Steam, with its last major version in 2021 the internal reference-sim study. We respect both lineages enough to measure ourselves against them, openly.

reference-sim — the realism benchmark

Closed source, earned reputation

Windows-only, sold from its own site, last major version 1.9.0 in 2021 the internal reference-sim study. We calibrate against its own slow-motion demo (53/56 checks, 0 failures the internal verification archive) and publish both scorecards, including what it still does better: licensed equipment art, extreme-spin cushion behavior, the true massé boomerang, and a mature online ecosystem the internal verification archive. Its replays cannot be independently verified; ours re-simulate bit-exactly anywhere.

What we don’t claim

  • Rendering is physically grounded, not yet benchmark-equal: the close-up is near the bar, the wide shot is not, held at ⚠︎ in our own report the internal verification archive.
  • Massé passes 5/6 checks; the re-accelerating boomerang needs a continuous-Magnus regime the analytic kernel excludes by design the internal verification archive.
  • Cushion constants are literature values plus fits, not first-party measurements, tracked open as issue #5 the internal verification archive.
  • The RL environment is potential, not product: deterministic, headless, numpy-native, but no gym wrapper ships today.
