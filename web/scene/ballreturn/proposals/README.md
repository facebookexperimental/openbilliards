# Track proposals

A proposal is a DERIVED runway family for a track another lane owns and exports — this lane derives from the reads, the
owning lane re-exports in its byte round; the committed track JSON is never edited here (gate t6d keeps it byte-identical to
the owner's export). `<trackId>.proposal.json`, schema `ball-return-track-proposal/1.0`: the reads with their tags and bands,
the variants drawn at the intervals' extremes (each a complete runway set the validator admits, with the derived exit lines,
wall stations, slopes and clearances), and the intervals that remain with the reason each remains. Nothing in a proposal is
authored: every number is a read, a band's extreme, or arithmetic on them, and says which.
